Household Hygiene Replenishment Reference

A governed vocabulary for depletion, planning, cadence, return, and recurring household hygiene.

Definitions, evidence, interpretation, and illustrative models are labeled separately.

How to read this reference

These entries are HygieneRoll working definitions. They say how this model uses a term. They are not empirical market facts, and they are not a claim that the wording is an industry standard, an official taxonomy, or a scientifically validated law.

Foundation v0.1 admits no external observations. A factual observation about actual markets, households, or companies requires an admitted external source before publication. An example used only to show the logic would be marked illustrative, and would not be described as measured behavior.

  • Project definitionA distinction HygieneRoll chooses and names. It points to the public page or method where the concept is used.
  • Observed evidenceA factual statement about the external world. It is published only with an admitted source. None are admitted in v0.1.
  • Derived interpretationA reading of admitted evidence. It stays in interpretive language and does not pretend the source stated the conclusion.
  • Illustrative modelA scenario or diagram used to explain logic. It is not a measured household or an average.

Core reference objects

HRK-001

HygieneRoll working definition

Replenishment vs Subscription

Definition

Within the HygieneRoll model, a subscription describes a recurring commerce arrangement, and replenishment describes planning around an item approaching renewed need or depletion.

Key distinction

Within the model, a subscription can be one mechanism for recurring commerce, and replenishment logic is concerned with the timing of need. The two can coincide, and they can also come apart: a fixed shipping interval does not, by itself, stand in for the timing of need on a particular item.

Why it matters inside the model

The model asks when the household is likely to need the item again, using the assumptions the visitor supplies. It does not treat a billing cycle as the definition of need.

Related artifact

Operationalized on the calculator and described in the replenishment model. Related entries: Planning Trigger and Illustrative Cadence.

Evidence posture

Project-defined. Defined within the HygieneRoll model. No external evidence is attached.

HRK-002

HygieneRoll working definition

Household Depletion Clock

Definition

The HygieneRoll model represents a household as containing multiple recurring essentials whose supply can deplete on different timelines, and it treats each item as an independent replenishment clock.

Key distinction

Within the model, the household is one customer relationship and its consumption is not one clock. Each item keeps its own replenishment clock, so different item inputs can produce different planning-trigger dates. The model does not collapse those clocks into one schedule.

Why it matters inside the model

The calculator operationalizes this by estimating each item on its own and then identifying the soonest planning trigger. That household summary does not average unlike items. This is a representation chosen by the model, not a research finding about how many cycles households have.

Related artifact

Operationalized by calculateHousehold() in the calculator engine, and visible when more than one item is estimated on the calculator. Related entries: Planning Trigger and Re-entry.

Evidence posture

Project-defined. Defined within the HygieneRoll model. No external evidence is attached.

HRK-003

HygieneRoll working definition

Planning Trigger

Definition

In HygieneRoll calculator v0.1, the planning trigger is the rounded depletion timing minus lead time minus safety buffer, clamped at zero. It is a scenario-derived planning threshold.

Key distinction

The trigger is the day the planning window opens under the visitor’s assumptions. It is not an optimal reorder point, a scientific reorder date, or a recommended purchase date. A result at or below zero is shown as now, not as a negative day.

Why it matters inside the model

Depletion timing alone does not say when a replenishment would need to be underway. Lead time and buffer are subtracted so the threshold sits earlier than the estimated depletion. The rounding rule is the one specified in the calculator methodology.

Related artifact

Specified in CALCULATOR_METHODOLOGY.md and calculated on the calculator. Related entry: Lead Time and Safety Buffer.

Evidence posture

Project-defined. Defined within the HygieneRoll model. No external evidence is attached.

HRK-004

HygieneRoll working definition

Lead Time and Safety Buffer

Definition

Within HygieneRoll calculator v0.1, lead time is the time assumed between initiating replenishment and availability or arrival.

Within HygieneRoll calculator v0.1, the safety buffer is a user-selected additional time before estimated depletion. It is not a medically safe stock level, an industry optimum, or a statistical confidence interval.

Key distinction

Lead time is about arrival. The buffer is extra time the visitor wants before the estimated depletion. They are separate inputs. Either may be zero. Neither is supplied by a hidden default, and neither is a health or sanitation standard.

Why it matters inside the model

Both are subtracted from depletion timing to form the planning trigger. Changing either one changes the threshold without changing the usage rate. The model does not infer a correct buffer from household size or from a category average.

Related artifact

Entered on the calculator and specified in CALCULATOR_METHODOLOGY.md. Related entry: Planning Trigger.

Evidence posture

Project-defined. Defined within the HygieneRoll model. No external evidence is attached.

HRK-005

HygieneRoll working definition

Illustrative Cadence

Definition

Within HygieneRoll calculator v0.1, illustrative cadence estimates how long a replenishment quantity would cover under the supplied usage assumptions. It is not an optimal subscription frequency, an automatic shipping recommendation, or a guaranteed usage interval.

Key distinction

Cadence here is coverage under a stated quantity and a stated usage rate. If the replenishment quantity is left blank, the calculator uses the current quantity for that illustration. The result is a planning picture, not a schedule the household is expected to keep.

Why it matters inside the model

Within the model, coverage follows the quantity and usage supplied for that item, so one interval need not fit every item. The label stays “illustrative” so the figure is not read as a recommended subscription.

Related artifact

Specified in CALCULATOR_METHODOLOGY.md and shown on the calculator. Related entry: Replenishment vs Subscription.

Evidence posture

Project-defined. Defined within the HygieneRoll model. No external evidence is attached. A numerical walkthrough, if one is shown elsewhere, is an illustrative model rather than observed usage.

HRK-006

HygieneRoll working definition

Ownership of Return

Definition

Within HygieneRoll, ownership of return describes controlling or directly operating the consumer-facing re-entry surface through which recurring household demand can come back. It does not mean legal ownership of consumers, ownership of their behavior, proven retention, or guaranteed recurring revenue.

Key distinction

Within the HygieneRoll model, product distribution and control of the consumer re-entry surface are separate concepts. Ownership of return names the latter. It is a strategic and commercial concept, not a claim that demand has already been captured.

Why it matters inside the model

The asset is built around the idea that recurring hygiene is valuable when the return path is direct. The reference states the idea. It does not report retention, revenue, or an operating history.

Related artifact

Stated on the homepage and carried through the replenishment model. Related entries: Re-entry and Category Expansion.

Evidence posture

Project-defined. Defined within the HygieneRoll model. No external evidence is attached.

HRK-007

HygieneRoll working definition

Re-entry

Definition

Within the HygieneRoll model, re-entry is the point at which a household returns to a consumer surface because a recurring need is approaching again. It is distinct from a first purchase.

Key distinction

A first purchase opens the relationship. Re-entry is the later interaction the model is built to represent: need, use, replenishment, and return. The model does not claim that every household behaves this way. It names the event the loop is organized around.

Why it matters inside the model

Without a distinct return event, replenishment collapses into a storefront that waits for the next unrelated visit. Re-entry keeps the next cycle attached to the same household need.

Related artifact

Described on the homepage and in the replenishment model. Related entries: Household Depletion Clock and Ownership of Return.

Evidence posture

Project-defined. Defined within the HygieneRoll model. No external evidence is attached.

HRK-008

HygieneRoll working definition

Category Expansion

Definition

The HygieneRoll category model treats paper hygiene as the clearest entry anchor, then personal care, then broader household hygiene. Paper hygiene is not the category ceiling. This sequence is a strategic model, not a claim that it is the empirically best expansion path.

Key distinction

HygieneRoll uses paper hygiene — tissue, rolls, towels, and wipes — as its entry anchor. Personal care and household cleaning are modeled as expansion layers. The order is an architecture choice. It is not a market-leadership claim and not a finding about the empirically best sequence.

Why it matters inside the model

The same replenishment relationship can cover more than one clock. Expansion, in this reference, means the surface is designed to hold those further essentials, not that a household has been observed to adopt them in this order.

Related artifact

Stated on the homepage and in the replenishment model. Related entry: Ownership of Return.

Evidence posture

Project-defined. Defined within the HygieneRoll model. No external evidence is attached.

Replenishment ontology v0.1

The ontology names every input and every calculated value the calculator uses, so a person or a machine can trace a result back to its inputs. Each term sits in one layer:

  • Project definitionA concept HygieneRoll defines, such as a product category or the scenario record.
  • Scenario assumptionA value you supply about your own household. It is not a measurement or an average.
  • Derived calculationArithmetic the engine performs on your assumptions. Each has a published formula.
  • Observed evidenceAn external measurement. Published only with an admitted source. None is admitted, and the engine never substitutes one for your input.

Identifiers are never reused. A change in meaning, unit, or formula issues a new identifier. The machine-readable version, with typed relationships and versioning rules, is reference/replenishment-ontology.json.

HRO-006 Usage assumption Scenario assumption record What the user enters about use: a usage method, and either weekly usage in item units or typical duration in weeks.
HRO-007 Variability allowance Scenario assumption percent A user-selected percentage, from 0 to 50, that widens usage into a slow and a fast bound. It is a planning allowance. It is not a probability, a confidence interval, or a measured spread.
HRO-008 Usage bounds Derived calculation item units per week The slow and fast consumption rates produced by applying the variability allowance to the consumption rate. slow = r × (1 − v); fast = r × (1 + v); v = variability_percent / 100
HRO-009 Depletion interval Derived calculation days The whole-day window in which current supply runs out under the fast and slow usage bounds. earliest = floor((q / fast) × 7); latest = ceil((q / slow) × 7); at v = 0 both equal round_half_up((q / r) × 7)
HRO-010 Fulfillment lead time Scenario assumption days The user's assumption of how many days a replenishment takes to arrive after it is ordered. Zero or more. There is no hidden default.
HRO-011 Safety buffer Scenario assumption days The extra days of supply the user wants to still have when a replenishment arrives. Zero or more. It is a preference, not an optimal stock level.
HRO-012 Lead-time demand Derived calculation item units The units consumed during the fulfillment lead time at the fast usage bound, rounded up to 0.01. ceil_0.01(lead_time_days × fast / 7)
HRO-013 Reserve stock Derived calculation item units The safety buffer expressed in item units at the fast usage bound, rounded up to 0.01. ceil_0.01(safety_buffer_days × fast / 7)
HRO-014 Reorder threshold Derived calculation item units The stock level at which ordering keeps the safety buffer intact under the fast usage bound. It is the stock-level expression of the planning trigger. lead_time_demand + reserve_stock
HRO-015 Planning trigger Derived calculation days The reorder window in days: the depletion interval minus lead time and safety buffer, clamped at zero. max(0, depletion − lead_time_days − safety_buffer_days), each end separately
HRO-016 Replenishment quantity Scenario assumption item units Units the user usually adds at each replenishment. When left blank, the current supply is used.
HRO-017 Replenishment cadence Derived calculation days The illustrative interval between replenishments: how long one replenishment quantity lasts under the usage bounds. It is not a recommended subscription frequency. same day-window rule as the depletion interval, with replenishment_quantity in place of q
HRO-018 Fixed delivery interval Scenario assumption days An optional fixed interval, in days, that the user wants to compare against the item's replenishment cadence, such as a subscription schedule they hold or are considering.
HRO-019 Subscription compatibility Derived calculation code Whether a fixed delivery interval falls inside the replenishment cadence window, and by how many days per cycle it drifts from it. A positive drift means supply shrinks each cycle. A negative drift means stock accumulates. EARLIER_THAN_WINDOW if interval < cadence.earliest; LATER_THAN_WINDOW if interval > cadence.latest; otherwise WITHIN_WINDOW; drift = interval − cadence, from latest (min) to earliest (max)
HRO-020 Stockout exposure Derived calculation days For a given order day and lead time, the days an item would be without supply before the replenishment arrives, at the slow (min) and fast (max) usage bounds. It is scenario arithmetic, not a probability of stockout. arrival = order_day + lead_time; max = max(0, ceil(arrival − depletion.earliest)); min = max(0, ceil(arrival − depletion.latest))
HRO-021 Lead-time slip Derived calculation days A sensitivity check: the planning trigger re-planned for a longer lead time, and the stockout exposure if the order was placed at the original trigger but arrived late. Offsets are fixed presentation values, not forecasts of delay. for each offset s: trigger(depletion, lead_time + s, buffer); stockout_exposure(order_day = trigger.earliest, lead_time + s)
HRO-022 Next household return Derived calculation record The item or tied items whose planning trigger begins soonest. Items are not averaged. items with minimum planning_trigger.earliest, in input order
HRO-023 Scenario record Project definition record The machine-readable output of one scenario. It holds every input and every derived value under the field names listed in this ontology, with the engine and ontology versions. It has no timestamp, so identical inputs produce an identical record.
HRO-024 Observed consumption rate Observed evidence — reserved, no value admitted item units per week A consumption rate measured for a stated population, geography, product, and period by an admitted external source. No value is admitted in this version. The engine never substitutes one for a user assumption.

How evidence enters the reference

An external fact is admitted only when a source exists, the source supports that exact sentence, and the scope, period, geography, population, and metric match. If any of those fail, the claim is blocked. It is not published in weaker wording that still asserts the fact.

Project pages are provenance for definitions. They are not evidence about the outside world. A derived interpretation is published only with admitted sources, and it stays in interpretive language. Illustrative scenarios will stay labeled as illustrations.

The source register admits no source. It keeps two market-research summaries under review. Their figures were removed from public pages until a source is admitted. Authority in this foundation is the refusal to blur a definition into an observation.

Apply the model

The calculator turns these definitions into a planning window from the visitor’s own inputs. The replenishment model is the operating reference the calculator implements. The homepage states the asset thesis those tools belong to.
